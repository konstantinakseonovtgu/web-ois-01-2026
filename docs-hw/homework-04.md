# Задание к практике 4

## Часть 1. Отмена записи (3 балла)

BR-5: отменить запись можно до начала мероприятия; место освобождается сразу.

`DELETE /api/events/{event_id}/registrations/{user_id}` — путь временный: когда появится вход,
он станет `.../registrations/me`.

| Ситуация | Ответ |
|---|---|
| активная запись есть, мероприятие не началось | 204; у записи `status = 'cancelled'`, строка **не удаляется** |
| активной записи нет (или уже отменена) | 404 |
| мероприятие уже началось | 409 |

После отмены студент может записаться снова — проверьте, что это работает, и объясните в
`docs/hw-04.md`, какая часть схемы это позволяет.

## Часть 2. Свободные места без N+1 (3 балла)

Добавьте в ответ мероприятия поле `free_seats` — сколько мест осталось (лимит минус активные
записи). Поле нужно и в `GET /api/events/{id}`, и в каждом мероприятии афиши `GET /api/events`.

Главное требование: **число SQL-запросов на афишу не зависит от числа мероприятий на странице.**
Решение «для каждого мероприятия отдельно посчитать записи» даёт 1 + N запросов — это и есть
N+1, и оно не принимается.

Проверка: включите `SQL_ECHO: "1"` и откройте `GET /api/events?size=20`. В `docs/hw-04.md`
напишите, сколько запросов к базе выполняется и сколько их было бы при решении «в цикле».

Ожидаемые значения на демо-данных: лекция про Яндекс — 38, турнир — 63, мастер-класс по Git — 1.

## Часть 3. Теги через миграцию (2 балла)

Мероприятию можно поставить несколько тегов, тег стоит у многих мероприятий (это уже было в
задании к практике 3 — теперь на моделях).

- Модели `Tag` и таблица связи `event_tags`; у мероприятия — `relationship` к тегам.
- Миграция через `make migration m="add tags"`. Прочитайте её перед применением.
- Проверьте откат: `docker compose exec api alembic downgrade -1`, затем `make migrate`.
  Таблицы тегов должны исчезнуть и появиться снова, остальные данные — остаться.
- Теги в `seed.py`: лекция про Яндекс — «лекция» и «IT», мастер-класс по Git — «IT»,
  турнир — «турнир», показ фильма — «кино».

## Часть 4. Гонка за аудиторию (2 балла)

Напишите `api/scripts/race_rooms.py` по образцу `race.py`: три запроса одновременно создают
мероприятия в одной аудитории на одно и то же время.

Запустите несколько раз и в `docs/hw-04.md` ответьте:
- сколько мероприятий создаётся и какие коды получают остальные;
- в ответах встречаются два разных текста ошибки — какой код их выдаёт и почему при
  одновременных запросах чаще появляется второй;
- что произошло бы, если бы ограничения `events_room_no_overlap` в базе не было.

## Критерии оценки

| Критерий | Баллы |
|---|---|
| Отмена записи: коды, статус вместо удаления, повторная запись работает | 3 |
| `free_seats` верный в обоих эндпоинтах; число запросов не растёт с размером страницы; ответ про N+1 | 3 |
| Теги: модели, миграция, откат и повторное применение, демо-данные | 2 |
| Гонка за аудиторию: скрипт и объяснение двух путей ошибки | 2 |
