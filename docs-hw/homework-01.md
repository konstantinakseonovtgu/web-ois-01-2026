# Задание к практике 1

Задание из двух частей. Первая — ТЗ на свою систему, вторая — небольшое расширение API WEB-ОИС.

## Часть 1. Техническое задание на свою систему (7 баллов)

Выберите тему из списка или предложите свою (согласуйте с преподавателем):

- бронирование переговорных в коворкинге;
- запись на тренировки в спортзал с ограничением мест в группе;
- обмен учебниками между студентами;
- заявки на ремонт в общежитии с исполнителями и сроками;
- библиотека настольных игр клуба: выдача и возврат;
- запись на консультации к преподавателям по слотам.

Напишите ТЗ по шаблону `tz-template.md`. Образец — `docs/tz.md` в репозитории WEB-ОИС.
Копировать формулировки из образца нельзя: проверяется, как вы думаете о своей системе.

**Требования к ТЗ**

| Раздел | Минимум |
|---|---|
| Проблема и цель | проблемы описаны через последствия («организатор не знает, сколько придёт»), а не через «нужен сайт» |
| Что НЕ входит | не меньше 3 пунктов с причиной |
| Роли | не меньше 3 ролей, для каждой — что может делать |
| Сценарии | не меньше 3 сценариев по шагам |
| Бизнес-правила | не меньше 5 пронумерованных правил; для каждого указано, где оно обеспечивается; хотя бы 2 правила могут нарушиться при одновременных запросах — объясните как |
| Нефункциональные требования | не меньше 4; каждое проверяемое (число, а не «быстро») |
| Модель данных | сущности, поля, связи |
| Выбор стека | не меньше 3 ADR; в каждом — контекст, не меньше 2 рассмотренных вариантов, решение и его цена |
| Жизненный цикл | схема статусов главной сущности: кто и каким действием переводит из одного в другой |
| Критерии приёмки | для 2–3 главных правил: исходные данные → действие → ожидаемый результат |
| API | не меньше 6 эндпоинтов: метод, путь, кто вызывает; коды ответов и формат ошибки |
| Окружения, этапы, глоссарий | разработка и рабочее окружение; не меньше 4 этапов с результатом; не меньше 5 терминов |

**Критерии оценки части 1**

| Критерий | Баллы |
|---|---|
| Проблема, цель, границы, окружения, этапы, глоссарий | 1 |
| Роли, сценарии, API | 1 |
| Бизнес-правила, жизненный цикл, критерии приёмки: конкретно, проверяемо, с местом обеспечения | 2 |
| Нефункциональные требования проверяемы | 1 |
| ADR: настоящие альтернативы и честная цена решения | 2 |

## Часть 2. Справочники в API WEB-ОИС (3 балла)

Начните с тега `lesson-01-end`:

```bash
git switch -c hw-01 lesson-01-end
```

В `api/app/main.py` добавьте:

1. `GET /api/clubs` — список клубов (минимум 3, данные в памяти, как `EVENTS`).
2. `GET /api/clubs/{club_id}` — один клуб; если нет — 404 с понятным `detail`.
3. `GET /api/rooms` — список аудиторий с полями `id`, `name`, `building`, `capacity`.

Проверьте каждый эндпоинт в Swagger (`/docs`), в том числе ответ 404 и ответ на `/api/clubs/abc`.

**Критерии оценки части 2**

| Критерий | Баллы |
|---|---|
| Все три эндпоинта работают | 1 |
| 404 возвращается с осмысленным `detail`, `abc` даёт 422 | 1 |
| Код в отдельном коммите с понятным сообщением, `.venv` не попал в репозиторий | 1 |
